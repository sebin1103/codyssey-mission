## 🗺 1. 큰 그림부터 (⏱ 약 40초)

> 📺 **화면**: `LIBRARIES.md` ─ **"0. 큰 그림부터 잡고 가기"** 섹션

JAVIS는 크게 네 가지 일을 합니다.

첫째, 마이크로 **소리를 녹음**해서 WAV 파일로 저장합니다.
둘째, 그 WAV를 **30초씩 잘라서** 구글 음성 인식 API에 보내 CSV로 저장합니다.
셋째, CSV에서 **키워드와 날짜로 검색**할 수 있습니다.
넷째, 이 모든 걸 **GUI 클릭 한 번**으로 할 수 있게 묶었습니다.

각 단계마다 필요한 라이브러리만 골라서 썼기 때문에, 녹음에 필요한 도구와 검색에 필요한 도구가 잘 분리되어 있다는 게 이 코드의 첫 번째 특징입니다.

## 📦 2. 사용한 라이브러리 (⏱ 약 1분)

> 📺 **화면**: `LIBRARIES.md` ─ **"1. 사용한 라이브러리 한눈에 보기"** 표

라이브러리는 크게 두 종류로 나뉩니다.

먼저 **파이썬 표준 라이브러리**는 총 8개를 썼습니다. `os`, `sys`, `csv`, `json`, `wave`, `datetime`, `threading`, 그리고 GUI를 위한 `tkinter`. 모두 파이썬을 설치하면 자동으로 같이 깔리는 모듈이라 별도 설치가 필요 없습니다.

> 📺 **화면**: **"1-2. 외부 라이브러리"** 표로 스크롤

**외부 라이브러리**는 단 두 개만 사용했습니다. `pyaudio`와 `speech_recognition`입니다.

이게 중요한데, **미션 제약상 외부 라이브러리는 녹음과 STT 두 작업에 한해서만 허용**됐습니다. 그래서 그 외 모든 기능 ── GUI, 검색, 북마크, 통계, 내보내기 ── 은 **전부 표준 라이브러리만으로 구현**했습니다.

`pyaudio`는 마이크에서 소리를 받아오는 데 쓰고, `speech_recognition`은 그 소리를 구글 음성 인식 API에 보내서 텍스트로 받아오는 데 씁니다. 둘 다 파이썬 표준 라이브러리로는 할 수 없는 일이라서 외부 라이브러리가 꼭 필요한 부분입니다.

> 📺 **화면**: **"💡 왜 구글 STT인가요?"** 콜아웃

`speech_recognition` 라이브러리는 여러 음성 인식 엔진을 통일된 API로 묶어주는 라이브러리이고, 그 중 `recognize_google()`은 **별도 API 키 없이 무료로 호출**할 수 있는 구글 웹 음성 API 엔드포인트입니다. 한국어 인식 정확도가 높아 학습용 미션에 가장 적합한 선택이었습니다.

## 🎙 3. 핵심 함수 ① 녹음 (⏱ 약 1분 30초)

> 📺 **화면**: `LIBRARIES.md` ─ **"3-2. 녹음 기능 — `record_audio_with_event`"** 섹션

녹음 기능에서 가장 까다로웠던 부분은 **"녹음 중인데 화면이 멈추면 안 된다"**는 점이었습니다.

만약 메인 흐름에서 녹음을 직접 하면 GUI가 얼어버립니다. 그래서 녹음은 **별도의 스레드에서 백그라운드로** 돌리고, **`threading.Event`라는 신호 객체**로 메인과 워커가 통신하게 만들었습니다.

> 📺 **화면**: `record_audio_with_event` 코드 발췌 부분

코드를 보시면 `while not stop_event.is_set()`이 보일 텐데, 메인 스레드에서 `set()`을 호출할 때까지 마이크에서 계속 PCM 청크를 받아옵니다. 사용자가 "녹음 중지" 버튼을 누르는 순간 신호가 켜지고, 반복문을 빠져나옵니다.

그 다음 **`try / finally` 패턴**이 핵심입니다. PyAudio의 스트림과 객체는 **사용 후 반드시 닫아야 하는 자원**이에요. 안 닫으면 다음 녹음 때 마이크가 안 잡히는 경우가 생깁니다. `finally` 블록은 정상 종료든 예외든 무조건 실행되니까, "어떤 일이 있어도 자원 정리는 한다"는 걸 보장합니다.

이 패턴은 처음 만들 때 빠뜨렸다가, 녹음 중지가 안 풀리는 버그가 생긴 뒤에 추가한 거라 특히 강조하고 싶습니다.

## 🔤 4. 핵심 함수 ② STT 변환 (⏱ 약 1분)

> 📺 **화면**: `LIBRARIES.md` ─ **"3-4. STT 변환 — `split_wav_to_chunks`"** 섹션

STT에서 흥미로운 결정은 **WAV를 30초씩 잘라서 보낸다**는 부분입니다.

구글 음성 인식 API는 한 번에 너무 긴 오디오를 받으면 정확도가 떨어지고 타임아웃이 자주 발생합니다. 그래서 표준 라이브러리 `wave` 모듈만으로 WAV의 임의 위치에 점프해서 30초 분량씩 잘라 읽었습니다.

`wf.setpos(offset)`이 그 위치 이동을 담당하고, `readframes(n)`이 거기서부터 n개 샘플을 읽습니다. **외부 오디오 라이브러리 없이도 표준 라이브러리만으로 충분**하다는 점이 인상적이었습니다.

각 조각마다 "원본의 몇 초에서 시작했는지"도 같이 저장하기 때문에, 최종 CSV의 "시간" 컬럼을 자연스럽게 채울 수 있습니다.

> 📺 **화면**: `transcribe_audio_file` 코드 발췌

구글 호출 부분도 중요한데, **예외를 두 종류로 나눠서** 처리했습니다. `UnknownValueError`는 그 30초에 인식할 음성이 없었다는 뜻이라 다음 조각으로 그냥 진행하지만, `RequestError`는 인터넷 자체에 문제가 생긴 거니까 더 진행해도 의미가 없어서 `break`로 중단합니다.

## 🖼 5. 핵심 함수 ③ GUI (⏱ 약 1분 30초)

> 📺 **화면**: `LIBRARIES.md` ─ **"3-8. GUI"** 섹션

GUI는 표준 라이브러리 `tkinter`로만 구현했습니다. 외부 GUI 프레임워크는 미션 제약상 사용할 수 없으니까요.

이 부분에서 두 가지 시행착오가 있었는데 짚어드리겠습니다.

> 📺 **화면**: **"검색 입력칸 — `tk.Entry`"** 부분

첫 번째는 **검색 입력칸 문제**입니다. 처음에는 더 예쁜 `ttk.Entry`로 만들었는데, macOS에서 **한글이 입력되지 않는 버그**가 발생했습니다. 알아보니 `ttk.Entry`와 macOS 한국어 입력기 사이에 호환성 이슈가 있더군요. 그래서 클래식 `tk.Entry`로 바꿨습니다. 디자인은 살짝 양보했지만, 한글이 안 입력되는 것보다는 훨씬 낫죠.

> 📺 **화면**: **"녹음 스레드 시작 / 종료"** 부분

두 번째는 **녹음 버튼 토글 문제**입니다. 처음 버전에서는 워커 스레드에서 예외가 나면 "녹음 중지" 버튼이 다시 "녹음 시작"으로 안 돌아오는 버그가 있었습니다. 이걸 해결하려고 워커 자체를 `try / except`로 한 번 더 감쌌습니다. 무슨 일이 있어도 메인 스레드에서 후처리가 반드시 실행되도록 보장한 거죠.

또 워커 스레드에서 GUI 위젯을 직접 건드리면 tkinter가 깨질 수 있어서, **`root.after(0, callback)` 패턴**을 썼습니다. 이건 "워커가 메인 스레드한테 이걸 대신 실행해줘"라고 부탁하는 방식인데, tkinter에서 멀티스레딩의 표준 패턴입니다.

## ⭐ 6. 보너스 기능들 (⏱ 약 1분)

> 📺 **화면**: `LIBRARIES.md` ─ **"3-6. 북마크"** 섹션

스토리에서 한송희 박사가 화성 일지를 작성한다는 설정이 인상적이어서, 일지 컨셉에 어울리는 보너스 기능을 세 가지 추가했습니다.

**첫째는 북마크 기능**입니다. 별표(★)를 단 중요 발화를 `json` 모듈로 파일에 저장합니다. 별도 데이터베이스 없이 표준 라이브러리 한 줄로 영속 저장이 가능하고, `ensure_ascii=False` 옵션으로 한글이 그대로 저장되어 사람이 직접 열어봐도 알아볼 수 있게 했습니다.

> 📺 **화면**: **"3-7. 통계 / 내보내기"** 섹션

**둘째는 통계 대시보드**입니다. 여기서 재미있는 게 **set 연산**을 활용했다는 점입니다. WAV 파일명 집합과 CSV 파일명 집합을 만들어서, 교집합은 변환 완료된 파일, 차집합은 미변환 파일로 **한 줄에 계산**됩니다. if문이나 for문 없이 set 연산 두 줄로 끝나는 깔끔한 코드라 보여드리고 싶었습니다.

**셋째는 검색 결과 내보내기**입니다. 키워드 검색 결과를 사람이 읽기 좋은 `.txt` 파일로 저장합니다. 파일별로 그룹핑해서 보고서처럼 보이도록 정리했습니다.

## 🎯 8. 정리 (⏱ 약 30초)

> 📺 **화면**: 다시 첫 페이지(혹은 표 화면)

정리하겠습니다.

이번 미션의 핵심은 **"외부 라이브러리 의존을 최소화하면서도 사용자 친화적인 시스템 만들기"**였습니다.

스레드 안전성, 한글 IME 호환, 자원 누수 방지 같은 실전 문제들을 다루면서 단순히 "동작하는 코드"가 아닌 **"안전하게 동작하는 코드"**를 만들려고 했습니다.

4. **예상 질문 대비**

   - *"왜 JSON으로 북마크 저장?"* → 데이터가 작아서 DB 오버킬. 표준 라이브러리만으로 영속 저장 가능.
   - *"PyAudio 대신 표준 라이브러리로는 안 되나?"* → 파이썬 표준 라이브러리에는 마이크 캡처 기능이 없음. 이 부분은 외부 라이브러리가 꼭 필요함.
